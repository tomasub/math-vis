# 1.2 Range, nullspace and solvability of Ax = b

Two linked stages (ℝⁿ input / ℝᵐ output, each independently 2D or 3D) with a shape control
for all four allowed shapes, a matrix editor, draggable **x** and **b**, both presets, a
gated Verdict panel, and a "Check yourself" predict→reveal mode.

## Math (`js/math/linalg.js`)
Added, with NumPy-fixture or property-based coverage: `applyRows`, `projectOntoBasis`
(b∈R(A) via residual vs tol, reusing `analyse`'s tol — no second tolerance),
`completeOrthonormalBasis` (extends the row-space basis with the standard basis to get an
orthonormal basis of N(A)), `gaussianSolve` (partial pivoting), `minNormSolve` (the
genuine minimum-norm x_p, valid for rank-deficient A: x_p = Σcᵢrᵢ over the orthonormal
row-space basis, c from the small normal equations). `gaussianSolve`, `projectOntoBasis`
and a `solvability` case (rank, nullity, minimum-norm x via SVD pseudo-inverse) are
checked against NumPy in `tests/make_fixtures.py`/`tests/run.js`. `completeOrthonormalBasis`
has no single correct numeric answer (any orthonormal completion is valid), so it's
covered by hand-written property tests (orthonormality, A·v ≈ 0) instead — noted as a
deviation from "every function gets a NumPy case".

## Toolkit additions
- `lines`/`planes` in both stages now take an optional `at` (default origin), so an affine
  set like x_p + N(A) (Lemma 1.1.2) can be drawn as a shifted copy — documented in
  stage2d.js's scene comment, demoed in `dev/gallery.html`.
- `dots` now take `label`/`labelColor` (both stages) for non-draggable markers (x_p,
  proj(b)).
- `ui.PredictReveal`: generic predict→reveal (options, hidden `correct` until revealed,
  `resetKey`), demoed in the gallery; reusable for 6.1.
- `--muted-weak` CSS token (for N(A)'s full-space tint when A = 0) and `.viz-figures`
  layout for two side-by-side stages.

## Verified against the catalogue/notes

## Deviations / open questions
- The Verdict panel is gated by "Check yourself" only when the user turns that toggle on
  (default off, so the panel is normally live, matching "Shows"); turning it on hides the
  three results (plus the distance) behind predict→reveal, satisfying "Check yourself"
  literally. I couldn't find stronger guidance on which reading was intended.
- `completeOrthonormalBasis` fixtures are property-based, not exact-value, for the reason
  above.

## Fix round (6 reviewed defects)

1. **Default b out of range.** `initial()` now uses b = A·[0.5, 0.5] = [1, −0.5, 2] (all
   |bᵢ| ≤ 3), so the first keyboard nudge on b no longer silently clamps it off R(A).
   Updated the default-state test's expected x_p and added the |bᵢ| ≤ 3 assertion.
2. **`randomizeB`'s in-R(A) branch.** Now scales the whole vector b = A·xr by 3/max|bᵢ|
   (not componentwise clamp) when it exceeds the box, keeping it exactly on the same ray
   through the origin, hence exactly in R(A). Measured over 2000 seeded draws: **100.00%**
   of in-R(A)-branch draws land in R(A) for both Example 1.1.1 and Example 1.1.2 (was
   26.6% / 22.8%). Added a 200-draw test that checks every in-R(A)-branch draw via
   `derive(...).bInR`.
3. **`applyPreset` stale b.** Presets now also set b in R(A): ex111 reuses the new default
   b (unique solution), ex112 uses b = A·[1,1,0] = [1,2,0] (infinitely many solutions, the
   case the preset exists to show). x is re-clamped to the new n. Added one test per preset
   asserting `bInR` and the verdict.
4. **Dead `xpTex`.** Now rendered in Live values, directly above `solutionTex`. Kept
   `Ax`/`b` rendered too (chose "show" over "remove" — they read naturally next to A).
5. **Decimal nullspace/range basis.** Added `L.niceBasis` (`js/math/linalg.js`): rescales a
   unit basis vector to the smallest integer vector along the same line when every entry
   matches a common rational (denominators ≤ 12) within tol, sign-normalised (first
   non-zero entry positive), else falls back to the vector unchanged. Used only for the
   TeX display of N(A)/R(A) (not the geometry in `scene()`, which still uses the
   orthonormal basis so plane/line rendering is unaffected). Example 1.1.2 now shows
   N(A) = span{[1, 1, −1]}, the same line as the notes' span[−1, −1, 1]. Added a muted note
   under Live values ("any non-zero multiple spans the same subspace"). No NumPy reference
   exists for "nicest integer scaling" (any multiple is equally correct), so covered by 9
   hand-written tests in `tests/run.js` instead, per the project's own precedent for
   `completeOrthonormalBasis`.
6. **proj(b) label collision.** Added a general `labelAt` field to `dots` in both stages
   (scene-format comment updated, demoed in `dev/gallery.html`): the label projects from
   `labelAt` instead of `at` when given. `solvability.js` sets it to a point 0.6 world
   units further from the origin along the same ray as proj(b), away from the Ax arrowhead.
   Verified in the 3×3 Example 1.1.2 state with b dragged out of R(A) — no overlap.
