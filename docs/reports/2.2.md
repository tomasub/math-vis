# 2.2 Shape vs solvability

**Built:** `js/viz/shape-solvability.js` (model + view), `tests/viz/2.2.test.js` (7 tests), manifest status `ready`.
No toolkit changes.

- Stage in ℝᵐ (m = 1 and 2 drawn in the plane): R(A) shaded, columns of A as arrows, 14 sample **b** as dots coloured unique / many / not solvable.
- Controls: m, n ∈ {1,2,3}, editable matrix entries (clamped to [−3, 3]), "Sample b".
- Classification uses `L.classifySolvability` (tol = 1e-10·max(1,‖A‖₂), shown in "Fixed by system").
- Verdict panel states which failure Thm 1.1.1 forces (tall / wide / square singular), counts per class, and the measure-zero note for tall A.
- Check yourself: predict "all" vs "almost none" solvable; the answer follows rank vs m, hidden until revealed.

**Deviations:** added a "b drawn from: R(A) only" switch, since with pure ball sampling a tall A never shows a solvable case. The default is the ball, as the catalogue says. The catalogue has no "Check yourself" for 2.2, so I wrote one.
Rank-deficient wide or square A is reported honestly: both failures can occur (the verdict says so).
Changing A keeps the same b samples in ball mode, so you can watch them reclassify.

**Numbers/notes:** only cites Thm 1.1.1 (from the manifest); no other equation numbers used.
**Open:** the stage has no draggable points (smoke says so, which is expected).
